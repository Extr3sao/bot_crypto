## 1. CLAIM

G-1 and G-2 made the hot stop durable and hot **inside
`AutonomousPaperRuntime`**. That runtime is reached by
`scripts/autonomous_paper.py` only. The product's *live* order paths are a
different program: `trading_bot.app`, whose four entrypoints talk to Bitunix
directly through `BitunixFuturesClient` and `MultiExchangeConnector`.

`HotStopGate` appears in exactly one module outside its own definition
(`autonomous/runtime.py`). Therefore:

> A `KILL_SWITCH` marker that stops the autonomous paper runtime does **not**
> stop `trading-bot run --mode live --auto-trade`, `place-order`,
> `close-position` or `set-tpsl`. The stop is scoped to a program, not to the
> account.

**G-3 closes that gap for the live entrypoints that exist today**, by putting
the same `HotStopGate` at the live execution boundary, and measures the result
rather than asserting it.

## 4. DECISION

### 4.1 The boundary goes at the app dispatch site, not inside the adapter

`BitunixFuturesClient` / `MultiExchangeConnector` are transport adapters used by
tests, scanners and future callers. Embedding a file-based policy in them would
make every constructor of an exchange client read the filesystem, and would hide
the authorisation decision two layers below the command that made it.

The boundary is therefore one context manager in `app.py`, and **every** live
sink call is lexically inside it. A structural test (ACC-G3-08) scans the AST
for the five sink attributes and fails if one is called outside
`_live_order_boundary`, so a new call site cannot be added without confronting
the gate.

This mirrors G-2's V-2 check; the difference is that `app.py` has seven sites in
four functions rather than one site in one function.

### 4.2 Entry is gated; reduction and protection are not

Blocking `flash_close_position` or `place_position_tpsl` during a stop would
*trap* the book: the operator engages the stop precisely when something is
wrong, and at that moment flattening and placing a protective stop must still
work. `HotStopGate` itself is neutral about intent; the caller classifies.

| Operation | Effect | `opens_risk` |
|---|---|---|
| `place_order` futures `trade_side=OPEN`, `reduce_only=False` | new exposure | **True** |
| `place_order` futures `trade_side=CLOSE` or `--reduce-only` | reduces exposure | **False** |
| `place_spot_order` `side=buy` / `connector.create_order` buy | new exposure | **True** |
| `place_spot_order` `side=sell` | releases inventory | **False** |
| `flash_close_position` | flattens | **False** |
| `place_position_tpsl` | protective | **False** |

The classification is a literal at each call site, so the AST test can read it
and a reviewer can disagree with one line rather than with a policy engine.

### 4.3 `run_dir` identity for a live process

A live bot is one long-lived process, not one directory per cycle. The run
directory is therefore **stable by default** (`data/live`) and overridable with
`--run-dir` on all four commands. Consequences, stated rather than implied:

- a restart without `--run-dir` reuses the same directory ⇒ G-1's persistence
  holds for live;
- a new `--run-dir` (or `--run-dir` pointing elsewhere) boots operational ⇒ the
  same limit G-1 recorded, now reachable in live. **No global latch is
  claimed.**
- `data/live/` is runtime state, not evidence: it is git-ignored, unlike
  `reports/autonomous-paper/<run-id>/`.

### 4.4 Fail-closed at dispatch

`_live_order_boundary` refuses entry when:

1. the marker is present or unreadable (`HotStopGate.poll`/`restore` semantics,
   unchanged from G-1);
2. the process-wide `KillSwitch` (`process_kill_switch()`, booted from
   `KILL_SWITCH_ENV`) is already active — a live path has no `DecisionEngine`
   rule 0 to catch it;
3. the switch object cannot be interrogated (`is_active` raises) — an exception
   is not permission;
4. the boundary lock cannot be acquired within the gate's timeout.

Refusal does not write a marker for case 2. `KILL_SWITCH_ENV` stays a boot-time
token whose semantics G-1 fixed; persisting it here would silently change them.

### 4.5 Concurrency

The broker call is made **inside** `order_boundary`, so the lock is held for its
duration and `engage()` cannot ACK while a dispatch is in flight. A marker
written by a *different* process cannot preempt a call that is already on the
wire — no file write can. The guarantee is therefore: **once the marker exists,
every subsequent dispatch is refused**, and no dispatch begins between the
marker and the next poll. This is identical to G-1/G-2 and is not overstated.

### 4.6 What is *not* changed

- `HotStopGate` and `hot_stop.py` are **not modified**: G-1's marker semantics
  and G-2's linearization stay byte-identical, so their verifiers keep their
  meaning.
- No disarm path. `--disarm` keeps exiting 2.
- `LiveTradingGate` (P-8) stays dead code: enabling it would change the live
  admission policy, which is not this gap.
- `paper_cycle.py` (G-4) is untouched and remains uncovered.

### 4.7 DEF-G3-01

`tests/unit/test_app_demo.py::test_main_kill_switch_not_implemented_returns_two`
is updated from "the command does not exist" to "the command refuses without
`--run-dir`": exit 2, empty stdout, argparse names the missing argument. It
still fails if the command silently succeeds, which is the property MT-0002
cared about.

## 6. Acceptance criteria

| ID | Criterion |
|---|---|
| ACC-G3-01 | Positive control: with no marker, E1 and E4 reach the instrumented broker exactly once. |
| ACC-G3-02 | With a marker, E1/E2/E4/E6 reach it **zero** times and report a stop reason. |
| ACC-G3-03 | A marker written by a **different process** (the real `kill-switch` CLI) blocks the next dispatch. |
| ACC-G3-04 | Two consecutive processes over the same `run_dir` keep the block; the second boots engaged. |
| ACC-G3-05 | An unreadable marker (directory in its place) blocks entry. |
| ACC-G3-06 | `KILL_SWITCH_ENV` active at boot blocks entry even with no marker. |
| ACC-G3-07 | E3/E5/E7/E8/E9 still reach the broker while stopped (reduction is not trapped). |
| ACC-G3-08 | AST: all seven sink call sites are lexically inside `_live_order_boundary`. |
| ACC-G3-09 | Concurrency: `engage()` does not ACK while a dispatch is in flight; the next dispatch is refused. |
| ACC-G3-10 | `--disarm` still exits 2; `hot_stop.py` is byte-identical to `a072da90`. |
| ACC-G3-11 | Each criterion above has a test that failed before the change (except ACC-G3-01, which must pass before *and* after) and passes after. |
| ACC-G3-12 | Mutants that remove the gate, remove the env check, invert `opens_risk`, drop the lock, or make the run dir per-process are killed. |
| ACC-G3-13 | A verifier other than the test suite re-derives ACC-G3-01…10 from the exported commit and reports `G3_VERIFIED_SCOPED`. |
| ACC-G3-14 | `TEST_TARGET == RUNTIME_TARGET`: the code exercised is the module the CLI loads (`trading_bot.app.__file__`). |

## 7. Out of scope

- G-4 (`paper_cycle.py`), D-6, strategy/risk/sizing/portfolio logic.
- Enabling `LiveTradingGate`, adding `--confirm-live` to `run`, or any change to
  live *admission* policy.
- Real feeds, real credentials, real orders, push.
- Global (cross-`run_dir`) stop: documented as a limit, not implemented.
- Power-loss durability on Windows: not claimed, same as G-1.

## 8. Verdict vocabulary

`G3_VERIFIED_SCOPED` requires ACC-G3-01…14 to pass **and** every
`RUNTIME_REACHABLE` row to carry a gate. Otherwise `G3_PARTIAL`; a reproducible,
uncorrected bypass is `G3_FAILED`. Independence is procedural (same author), so
the verdict never says "independently audited".
