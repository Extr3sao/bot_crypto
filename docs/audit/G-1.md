## 1. CLAIM

G-2 stops a **running** process: `<run_dir>/KILL_SWITCH` engages the gate. Nothing
in that design reads the file at construction, so a restart of the same run
boots `NORMAL` and the next `run_cycle` can dispatch again. The operator who
stopped a runaway loop therefore has two moves: keep the process alive forever,
or lose the stop by restarting it — which is exactly the moment a crash, a
supervisor restart or a deployment makes likely.

**G-1 closes that gap for one scope**: the run directory. If the marker is
present when a process starts, the process is engaged **before** any broker
call can begin, for the life of that process, with no way to rearm without
deleting the marker out of band. Scope is stated in §4.6, not implied.

## 4. DECISION

### 4.1 Authority: the marker, read at construction

`HotStopGate.__post_init__` calls `restore()`, which stats the control path and,
if the entry exists, engages before returning. Every construction path therefore
starts closed: the runtime, a test, a script, the next process. The first broker
call in the runtime is inside `order_boundary` (`runtime.py:1483`), which is only
reachable after the constructor. There is no window to close.

`restore()` is not a second gate. It is the same `engage()`, with
`origin="restore"`, so the lock, the switch activation, the fail-closed ordering
and the audit are identical to a hot engage.

### 4.2 Presence, not content

The marker's **existence** is the request; its content is the operator's reason.
An empty, binary, truncated or otherwise odd file still stops the process. A
file whose content fails to decode is read with `errors="replace"`.

### 4.3 Fail closed on every other answer

| Observation | Decision |
|---|---|
| `lstat` → `FileNotFoundError` | absent: the only answer that leaves the gate open |
| entry exists (file, directory, dangling symlink, device…) | **engage** |
| `lstat` raises anything else (`PermissionError`, `NotADirectoryError`, I/O) | **engage**, reason `control_file_unreadable:<Exc>` |
| read raises | **engage** (`path` is present, so the stop is already requested) |

`Path.exists()` is deliberately not used: it swallows several `OSError`s and
would report a dangling symlink as absent.

### 4.4 Durability, not just memory

`engage()` writes the marker itself (`_ensure_marker`), using
`write_control_file()`: write a uniquely named temp file in the same directory,
`flush`, `fsync`, `os.replace`, then best-effort `fsync` of the directory
(POSIX; on Windows the directory handle cannot be opened and the call is
skipped, which is stated as a limit rather than assumed away). A crash between
the marker write and the ACK therefore leaves the next boot blocked.

If persistence fails, the gate is still engaged in memory and the ACK says
`persisted: false`. A `true` is never reported for a marker that was not
written. The CLI keeps its own exit-code semantics: exit 0 means "the request is
on disk", it never means "the process is engaged".

**The JSONL audit is evidence, never authority.** `restore()` does not read it;
deleting `kill_switch_events.jsonl` cannot rearm anything.

### 4.5 Monotonicity is unchanged

No `disarm`, no rearm, no automatic clearing when the loop exits cleanly.
`--disarm` still exits 2. The only ways back to trading are a new process with
the existing explicit off token **and no marker**, or an operator deleting the
marker with the filesystem permission that also guards `STOP`.

### 4.6 Scope: the run directory, stated plainly

The marker lives in `run_dir`. Therefore:

- a restart that **reuses** the run id is blocked — this is the supervisor path
  (E-8) and any `--run-id` invocation;
- a restart with a **new** run id, or a different `--run-root`, is a new
  directory and boots operational. `scripts/autonomous_paper.py` generates a
  timestamped id by default (E-7), so a bare `python scripts/autonomous_paper.py`
  does **not** inherit an earlier stop.

This is a real limit and it is pinned by a test that asserts the bypass
(`test_a_new_run_dir_is_outside_the_persisted_scope_this_is_the_documented_limit`),
so no later report can claim global protection without changing that test.

No global latch is introduced. A latch under the run root would be unclearable
(`--disarm` is refused by contract), which would turn one stop into a permanent
inability to start any new paper run — a worse failure than the one it fixes. A
cross-run latch needs a policy decision (`engage` scope, clearing authority),
and that is a separate contract, not an implementation detail.

### 4.7 What a checkpoint cannot do

Startup reconciliation restores broker, risk and intents from
`data/storage/autonomous_paper_state.json` (E-10). It runs **before** the runtime
exists and never touches the marker; `restore()` runs after it. A checkpoint
written before the stop therefore cannot re-enable anything: the gate is
constructed from the marker, not from the book.

## 6. Requirements

| ID | Requirement |
|---|---|
| REQ-G1-01 | **Persistent.** A valid activation stays in force when the process exits or restarts over the same `run_dir`. |
| REQ-G1-02 | **Restored before dispatch.** A marker present at construction engages the gate before any broker call can begin, and before `run_cycle` runs. |
| REQ-G1-03 | **Checkpoint-proof.** Restoring a pre-stop checkpoint cannot re-enable dispatch. |
| REQ-G1-04 | **Fail closed.** Unreadable, malformed, replaced-by-directory or otherwise anomalous markers block; they never allow. Only proven absence allows. |
| REQ-G1-05 | **Atomic marker.** Creation/update is temp + `fsync` + `os.replace` (+ directory `fsync` where the platform allows it); a failed write leaves the previous marker intact. |
| REQ-G1-06 | **Crash window.** Persisting the request and dying before the ACK must still block the next boot. |
| REQ-G1-07 | **Audit is not authority.** No JSONL event is read to decide state; every restored stop writes its own `restored` event. |
| REQ-G1-08 | **G-2 unchanged.** `order_boundary` lock semantics, the `engaged` ACK, monotonicity, `--disarm` exit 2 and the boot-token policy are untouched. |
| REQ-G1-09 | **Honest scope.** The run-directory limit of §4.6 is documented and tested; no global claim. |

## 11. Stop conditions

Abort and report `BLOCKED_*` instead of a PASS if: a second dispatch site
appears in the autonomous runtime; the gate is constructed after a possible
dispatch; the marker write cannot be made atomic on this platform; any change
lands outside §8; or a required scenario cannot be exercised without a live
feed, real credentials or a real order.
