## 2. What the survivors *do* constrain

Two constraints are genuine, because they are committed text:

- **C-1** MT-0004 is about **negative tests** — tests that demonstrate a control
  fails when the thing it guards is absent. The parenthetical is the only
  description there is, but it is explicit.
- **C-2** MT-0004 is scoped to the kill-switch surface: it is named in the same
  sentence as MT-0003, in a comment about the two safety subcommands. It is not
  a licence to test unrelated modules.

Everything below is derived from those two constraints plus the behaviour that
actually exists in the tree. Where a criterion is my design decision rather
than a recovered requirement, it is marked **[REISSUED]**.

## 3. Problem this task solves

MT-0003 shipped rule 0 and a 35-case suite. That suite proves rule 0 works
**while it is present**. It cannot tell you whether it is *doing the work*, or
whether the suite would still be green if the control were removed, weakened,
or made to fail open. Concretely, three holes are visible in the current tree:

1. **No reproducible proof of sensitivity.** The MT-0003 run recorded a manual
   mutant ("13 failed / 15 passed"), but the mutant is not in the repository:
   nobody can re-run it, and nothing fails if `decision.py` drifts away from
   the anchors that made it possible.
2. **The block is asserted on outcomes, not on mechanism.** A blocked decision
   is checked for `mode`, `reason` and `orders_created`, but not for the
   property that matters operationally: *the broker was never called at all*,
   and the risk engine's advisory PASS could not have produced an order.
3. **Malformed packets can preempt the stop.** `decide` raises `ValueError`
   for an advisory risk review on an authorising packet. Rule 0 runs first, so
   a halted process returns `NO_TRADE` instead of raising — an ordering
   property with no test.

**[REISSUED]** Deliver a **negative-control certification** of the MT-0003
gate: a permanent, reproducible mutation matrix plus the negative behaviour

If a failing control can only be fixed by editing `src/**`, the correct outcome
is `BLOCKED`, not a production edit inside a tests-and-docs task.

### 4.3 Non-goals (explicitly out of scope)

- G-1 persistence, G-2 CLI activation, G-3 live bypass, G-4 duplicate engine.
  None of them is closed by this task, and no criterion below claims they are.
- Any live order, any exchange credential, any real capital.
- Refactoring `kill_switch.py` (ORPHAN) or removing `paper_cycle.py`.
- Reworking MT-0003's assertions. The new suite adds cases; it never relaxes one.

## 5. Acceptance criteria

### AC-1 — The matrix is reproducible from a git revision [REISSUED]

`scripts/audit/negative_controls.py` exports a revision with `git archive`,
runs the target suites unmutated (must pass), then runs them against each
declared mutant of `src/trading_bot/autonomous/decision.py` (each must fail).
Exit 0 only when the control passes **and** every mutant is killed. The script
must assert that the imported `trading_bot` comes from the mutated tree — a
mutant that never got imported proves nothing.

### AC-2 — Every declared mutant is killed, and the reason is recorded [REISSUED]

The matrix must contain at least six mutants, each an exact, single-occurrence
string replacement, and must fail closed if an anchor no longer matches:

| # | Mutant | Property it removes |
|---|---|---|
| M1 | rule 0 removed from `decide` | the gate itself |
| M2 | rule 0 removed from `intend` | the early stop before risk/verifier |
| M3 | `except Exception` branch returns `None` | fail-closed on an unreadable state |
| M4 | the engaged test becomes `if False:` | the block, keeping the plumbing |
| M5 | `active or state is not NORMAL` → `state is not NORMAL` | the redundant flag check |
| M6 | unknown `TRADING_BOT_KILL_SWITCH` value boots `NORMAL` | fail-safe boot policy |

The report must name, per mutant, at least one test that failed because of it.

### AC-3 — A blocked decision never reaches the broker [REISSUED]

With an engaged switch and a packet that would otherwise authorise (admitted
strategy, positive net edge, verifier PASS, risk PASS), the real
`AutonomousPaperRuntime` must: create zero orders, leave the broker with zero
`execute_signal` calls and no positions, and still record the risk engine's
verdict — proving the block came from rule 0 and not from another control.

### AC-4 — A malformed packet cannot preempt the stop [REISSUED]

`decide` on an advisory-risk / authorising packet raises `ValueError` while the
switch is `NORMAL`. With the switch engaged the same packet must return
`NO_TRADE` / `KILL_SWITCH_ACTIVE` and must not raise: a halted loop keeps
reporting, it does not crash.

### AC-5 — Only an explicit "off" token boots the process trading [REISSUED]

`TRADING_BOT_KILL_SWITCH` is normalised (strip + lowercase). `halted`,
`HALTED`, ` halted `, `yes` and any unrecognised non-empty value boot engaged;
only `""`, `0`, `off`, `normal`, `false`, `no` boot `NORMAL`. This extends
MT-0003's five-case table to the boundary of the off-whitelist.

### AC-6 — A mandatory contract cannot silently become untracked again [REISSUED]

`tests/unit/test_audit_contracts_tracked.py` must fail when any contract listed
in the backlog is missing, empty, gitignored, or untracked, and when the
backlog stops parsing as YAML or loses a required key. This is the durable fix
for the failure that produced `BLOCKED_SPEC`.

## 6. Test plan

| Level | Requirement |
|---|---|
| A. Unit / contract | AC-4, AC-5, AC-6 as pytest cases in the two new files. |
| B. Integration | AC-3 through the real `AutonomousPaperRuntime` composition used by MT-0003's tests (`tests/unit/autonomous/helpers.make_runtime`), not a hand-rolled stub. |

| D. Adversarial | The mutation matrix (AC-1, AC-2). A mutant that survives is a failure of the task, not a warning. |
| E. Regression | `tests/unit/autonomous/` and `tests/unit/test_app_cli_contract.py` must stay green. The full suite may be skipped only with the reason recorded. |

## 7. Verification requirements

- `BUILDER != VERIFIER`: verification runs **after** the commit, against trees
  exported from that commit, and re-derives every claim from git + fresh test
  runs. It must not read this document as evidence of itself.
- Every deliverable is referenced by sha256 in the run report.
- `FALSE_SUCCESS` must be 0 or reported as an incident. A mutant surviving is a
  `FAILED` verdict, never a footnote.
- The verdict vocabulary is `VERIFIED_SCOPED` / `RUNTIME_VERIFIED` / `PARTIAL` /
  `BLOCKED` / `FAILED`. `GLOBAL_GATE_VERIFIED`, `LIVE_READY` and
  `PRODUCTION_READY` are outside this task's power to grant.
