Checkpoint: **MA-DIRECTION-ARBITRATION-AND-POC02-REPAIR-01** · Base: `53c5910`
Evidence: frozen POC02 baseline (`POC02_PRE_REPAIR_BASELINE.*`), source audit of
`multi_agent/{opportunity,debate,decision,specialists,swarm}.py`,
`research/families/*.py`, `demo/paper_multi_agent.py`, `demo/poc02_runner.py`.

## B1 — Semantic model of simultaneous LONG/SHORT (DIR-02)

**Classification: ALTERNATIVE_DIRECTIONS.**

Evidence chain:

1. **Family source (`research/families/momentum_family.py`)**: one `generate()`
   call evaluates `histogram > 0 and momentum > +thr` (→ LONG) and the mirror
   `histogram < 0 and momentum < -thr` (→ SHORT). The conditions are mutually
   exclusive on the same indicator values — the two signals are the two sides
   of **one directional evaluation**, never two independent hypotheses.
   Identical mirror structure in `trend`, `breakout`, `mean_reversion`,
   `volatility` families.
2. **Runtime composition (`demo/paper_multi_agent.py:_proposal_set`)**: the
   POC02 runner loops `for direction in ("LONG", "SHORT")` and builds **one
   fixture family per direction**, submitting both resulting proposals into
   the same board/debate. The composition layer treats the two sides as if
   they were independent claims — the family semantics do not.
3. **Conflict semantics (`opportunity.py:OpportunityBoard._conflicts`)**: same
   asset + opposite direction + overlapping validity ⇒ `ConflictCase`. The
   board already models opposite directions of one window as *one conflict* —
   i.e., as alternatives competing for a single slot.
4. **Router (`debate.py:DebateRouter`)**: a `ConflictCase` produces
   `DIRECTIONAL_CONFLICT` + `MATERIAL_COUNTER_SIGNAL`, so both sides always
   enter debate together.
5. **Critic (`debate.py:CounterSignalCritic`)**: any same-asset position with
   the opposite direction is surfaced as counter-signal — with no distinction
   between "the mirrored alternative generated by the same evaluation" and
   "independent evidence contradicting the claim".
6. **Decision (`decision.py:_eligibility`)**: `DebateOutcome.UNRESOLVED` ⇒
   `INELIGIBLE_UNRESOLVED_CONFLICT`.

`AMBIGUOUS_CONTRACT` is rejected: no RFC/test asserts independent-direction
proposals; the mirror generation in the families plus the board's conflict
model demonstrate the ALTERNATIVE_DIRECTIONS reading. `INDEPENDENT_PROPOSALS`
is rejected: nothing in the family source produces two *independent* signals
(the conditions are complements on one feature vector).

## B2 — Root cause (DIR-03)

| Field | Value |
| --- | --- |
| ROOT_COMPONENT | **Composition layer** (`_proposal_set` fixture-family loop in `demo/paper_multi_agent.py`) upstream of a genuine contract gap in the MA-3/MA-4 seam |
| ROOT_SYMBOL | `_proposal_set(directions=("LONG","SHORT"))` → `OpportunityBoard.snapshot()` conflicts → `CounterSignalCritic.critique()` → `DebateReport.outcome=UNRESOLVED` → `DecisionEngine._eligibility()` |
| ROOT_CONTRACT | MA-3 `CounterSignalCritic` (treats every opposing same-asset proposal as TRUE_COUNTER_EVIDENCE) × MA-4 `INELIGIBLE_UNRESOLVED_CONFLICT` gate |
| FAILURE_MECHANISM | Both directions of one evaluation are admitted as simultaneous claims; each becomes the other's standing CHALLENGE (materiality 0.8); debate deterministically terminates UNRESOLVED (no revision action is requested, no new evidence can appear, `max_rounds` accounting ends the session); every candidate is then ineligible. With the POC02 composition submitting both directions every cycle, **valid opportunities are deterministically prevented from reaching Decision/Risk** — 18/18 candidates, 33/33 windows. |

Note the chain has *two* coupled layers: (a) the composition submits mutually
exclusive alternatives as simultaneous independent claims, and (b) the
critic/decision contracts have no representation for an
`EXPECTED_ALTERNATIVE_DIRECTION` group, so the group cannot be resolved to one
side before critique. (a) is the trigger; (b) is the contract gap that turns
the trigger into a deadlock. The repair therefore needs both the group +
arbitration contract (TRACK D) and the conflict-semantics distinction (D3).

**COUNTERSIGNAL_CRITIC_DEFECT: NO** — the critic behaves exactly as its
contract says ("adversarial search for opposing proposals inside the MA-2
set; surfaces counter-signals; never rejects a proposal by itself"). The
defect is that mutually exclusive alternatives of one evaluation are *fed to
it* as independent claims. The critic is NOT weakened by the repair.

## D3 — Conflict semantics contract (DIR-04)

Two distinct situations that the old pipeline conflated:

- **EXPECTED_ALTERNATIVE_DIRECTION**: the opposite-direction proposal produced
  by the *same directional evaluation* (same family call, same feature vector,
  complementary condition). Membership is proven structurally: both
  candidates descend from one `OpportunityGroup` (same strategy, asset,
  timeframe, decision window). This is **not** independent counter-evidence;
  it must be resolved by deterministic arbitration BEFORE critique.
- **TRUE_COUNTER_EVIDENCE**: an opposing signal derived from an *independent*
  evidence source (different strategy family, different regime engine verdict,
  explicit regime incoherence). This retains full critic authority: the critic
  may veto/unresolve.

Arbitration is scope-limited to groups formed **within one strategy family ×
asset × timeframe × decision window**. Cross-strategy opposition is never
arbitrated — it stays a genuine conflict for the critic.

## TRACK C — Strategy runtime reachability (STR-01..03)

All five `STRATEGY_EXPERT_FACTORIES` entries (momentum, trend, breakout,
mean_reversion, volatility) are registered by `register_swarm_agents()` and
invoked by the swarm loop — **invocation is NOT the problem**. But in the
POC02 runtime (`poc02_runner.run_cycle → _proposal_set`), the strategy experts
from `STRATEGY_EXPERT_FACTORIES` are never consulted: `_proposal_set` builds
only the `_FixtureFamily(direction)` momentum-echo pair. Reachability
classification per strategy in the **POC02 runtime path**:

| Strategy | Registered | Invoked (swarm contract) | Runtime reachable in POC02 path | Evidence |
| --- | --- | --- | --- | --- |
| momentum | YES | YES | **NO (canonical families bypassed)** — only `_FixtureFamily` echo proposals reached Decision (18 candidates, all `family_name="momentum"`) | POC02_ATTRIBUTION.jsonl: strategy_id=momentum only; `_proposal_set` source |
| trend | YES | YES | NO — canonical `TrendExpert` never called on runtime path | same |
| breakout | YES | YES | NO — same | same |
| mean_reversion | YES | YES | NO — same | same |
| volatility | YES | YES | NO — same | same |

**DEF-STRAT-RUNTIME-001 (LEGACY_STRATEGY_RUNTIME_REACHABILITY)** — registered:
the POC02 runtime composition bypasses the five canonical strategy experts and
submits a deterministic momentum-echo fixture pair instead; no canonical
strategy evaluation ever reaches the board. This is a composition defect, not
an expert defect. **Not activated automatically** — the replacement campaign
manifest freezes the corrected composition; no strategy parameter changes.

Distinguishing statuses for every cycle (STR-02): the runtime path produces
`PROPOSAL_GENERATED` (fixture echo) for momentum; trend/breakout/
mean_reversion/volatility are `NOT_RUNTIME_REACHABLE` (distinct from
`INVOKED_NO_SIGNAL`, which is what the canonical swarm path would report on a
quiet market; also distinct from `NOT_APPLICABLE`/`ERROR`, which do not occur
in the audit).
