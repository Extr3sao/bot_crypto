## What this work package had to prove

That `ruff format --check .` can exit 0 on this trunk **without** rewriting a single byte that
a committed record certifies, and that the mechanism used to get there cannot silently widen.

## The change, in the smallest terms

`pyproject.toml`, `[tool.ruff.format]` only: 24 exact file paths, generated from the
declaration rather than typed, no directory, no glob, no lint exclusion, no threshold moved.
Two scripts and one test were added to keep it that way: a guard that fails on eight
distinct kinds of drift, a generator for the comparison artefacts, and a suite test that runs
the guard.

## What the exemption costs, and why it is still the right call

Formatting those 24 files turns **six** certification tests red — three inside
`-m "not slow and not market"`, three more marked `@pytest.mark.slow` — because those tests
re-derive the digest of a committed artefact whose provenance includes the producer's exact
bytes. The alternative to exempting is to regenerate six certification records, which is a
decision about other lanes' evidence and is forbidden to this work package. So the gate is
closed where it can be closed, and the remaining hole is not only documented but fenced:
8 checks, 11 mutation controls, and a suite test.

The structural fix remains what WP-003-07 named — pins that certify a semantic fingerprint
instead of bytes — and this WP was explicitly forbidden from doing it.

## The blocker that actually stands between this repo and paper trading

It is not the format gate. It is that **the trunk cannot reproduce its own evidence**: 44 of
the red nodes are missing files that were never committed, and the tests that certify
producer provenance still hash bytes rather than meaning. Until the artefacts are
regenerated by their owning lanes and the pins move to a semantic fingerprint, any clean
checkout of this repository will disagree with the records it ships.

## One operational note that matters for the next run

This session opened on an emptied workspace: every worktree under `Downloads/bot*` had lost
its files and the primary `.git` had lost `HEAD`, `config`, `refs` and `index`. The object
database survived intact (1 219 commits, `fsck` clean) and the repository was rebuilt from it,
with `origin` recovered and verified by `git ls-remote`. Everything committed survives.
Everything that was only on disk — gitignored reports, `data/raw` caches, other lanes'
uncommitted edits — is gone, and that is the difference between the 95 red nodes of
WP-003-07 and the 103 measured here. Back this host up before the next long run.
